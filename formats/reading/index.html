    The reading file¶

    A study is one piece of research: the experiments one paper reports, or one project that has no paper yet. The bounds file says which GEO Series and papers belong to a study. The study's reading says what each sequenced sample is: the species, the tissue, the treatment, the assay, and which label the study varied between its samples. Each statement comes with the words that back it, the words that speak against it where the sources disagree, and a probability. The reading file writes that down, one file per study, as YAML. This page is all you need to read one.

    seqforge study check-reading reading.yaml
seqforge study relations reading.yaml

    The first command checks a file against this page. The second command prints what the reading implies between its samples, such as replicates and contrasts.

    The file at a glance¶

    A reading file has five parts. The arrows show how one part points at another.

    flowchart TD

    Read it from the samples outward. A sample's claims are its own row plus whatever shared adds. A claim that is backed by a source gives passage numbers, and each passage names the record or the paper that holds the quote. A claim that a source contradicts names that passage too, under against. A claim on a label that the study varied also names its level.

    An example¶

    A liver study of two ages. Each age has one pull-down library and the input library made from the same chromatin. The paper gives the old mice a different age from the records.

read_detail: The Series, its four samples, and the abstract of the one paper.

    The fields¶

    Every field below is required unless the table says otherwise. A file with any other top-level field is rejected.

    Field Holds
    format The whole number 2. See When the format changes.
    study The study's name: the GEO Series it was picked by, such as GSE100021.
    models Who wrote the file. reading is the model that read the study. probabilities is the model that gave the p values. Either may be null.
    read What the model read: one or more of records, abstract and full_text. No other word is accepted.
    read_detail Optional. One sentence that says which records and which paper.
    ontology_snapshot Where the file's ontology ids came from, written once: source names the dated snapshot of the ontologies, or the service the ids were looked up in, and date is its date, written 2026-11-21. For ids from liulab-data's ontology store, date is the UTC day the pass pinned the store's snapshots. Required when any claim has a term, except a term on sex, which is a word of this page's own.
    passages The quotes that back the claims, each under its number. May be empty: {}.
    factors The labels the study varied on purpose, each under its label. May be empty: {}.
    shared The claims that every sample has unless its own row says otherwise. May be empty: {}.
    samples One row per sequenced sample, each under the sample's id, such as GSM2668015. At least one.

    Passages¶

    A quote is written once in the file, however many claims it backs. passages is keyed by number: a whole number, 1 or more. Each passage holds the quote and where it was read, in one of two ways.

    Field Holds
    quote The words, copied from the source as one unbroken span.
    record and field For a quote from a GEO record: the record, and the field of it.
    paper and section For a quote from a paper: the paper, written pmid:<number>, and the section of it.

    record takes one of three forms:

    • one record id, such as GSE100021 or GSM2668015;
    • a list of record ids, when each of those records holds the quote in that field;
    • the word each_sample, when every sample record of the study holds the quote in that field.

    A record quote is exact: the field holds it character for character. A paper's text comes with markup and broken lines, so a paper quote is exact after the markup is removed and each run of white space is collapsed to one space.

    Claims¶

    A claim is one label of one sample: what the label's value is, how that is backed, and how sure the model is. In the example, tissue: {text: liver, ...} is one claim.

    Field Holds
    text The value, in the source's own words.
    term An ontology id for the value, such as UBERON:0002107. Written only when the match is clear. On treatment only, a list of ids when one sample got several compounds.
    value For an age, a dose, a duration or a label of the study's own: the number, or a range as [low, high]. YAML reads 1.7e12 as text, so write 1.7e+12.
    unit The unit of value, as one word: month, day, hour.
    level On a label that is a factor: the name of the sample's level. See Factors.
    id On biosample and donor: a short name made up in the file, such as B1.
    quoted Backing mark. A source says it: the numbers of the passages that say so.
    inferred Backing mark. No passage says it outright: a short text saying how it was worked out.
    unknown Backing mark. What was read does not say: a short note.
    na Backing mark. The label does not apply to this sample: a short text saying why.
    see Optional, and not beside quoted: the numbers of the passages the claim rests on.
    against Optional, beside any backing mark: the numbers of the passages that say otherwise.
    p A number from 0 to 1, or null. Required.

    Only p and one backing mark are required. A claim with any other field is rejected.

    The rules for a claim:

    • It has exactly one of quoted, inferred, unknown and na. None is rejected, and so are two.
    • quoted lists at least one passage.
    • Every number in quoted, in see and in against must be a passage in the file.
    • The text after inferred, unknown or na cannot be blank.
    • A quoted claim and an inferred claim say something: each has text or value. A biosample claim and a donor claim may have an id and neither of the two.
    • An unknown claim and an na claim give no value. So neither has text, term, value, unit or level.

    The four backing marks answer three questions in turn:

    flowchart LR
    A(["Does the label apply<br/>to this sample?"])
    B(["Can its value be told<br/>from what was read?"])
    C(["Does a passage<br/>say it outright?"])
    NA["<b><code>na</code></b><br/>why it does not apply<br/><i>no value</i>"]
    UNK["<b><code>unknown</code></b><br/>a short note<br/><i>no value</i>"]
    Q["<span style='color:#fff'><b><code>quoted</code></b><br/>the passage numbers<br/><i>has a value</i></span>"]
    I["<span style='color:#fff'><b><code>inferred</code></b><br/>how it was worked out<br/><i>has a value</i></span>"]

    A -->|yes| B
    A -->|no| NA
    B -->|yes| C
    B -->|no| UNK
    C -->|yes| Q
    C -->|no| I

    against is for sources that disagree. When the records say one thing and the paper another, the claim writes the value it judges right, backs it as usual, and lists the passages that say otherwise under against. Its p is the chance that the value it wrote is the right one. A passage that the claim merely does not use is not against it: against names a contradiction. A factor is a claim, so a factor can have against too.

    unknown and na are different gaps. unknown means that the label has a value and nothing that was read gives it. na means that the label has no value for this sample, such as the cell line of a tissue sample.

    p is the chance that the claim as written is right, given what read lists. A model judged it. On an unknown claim, p is the chance that what was read really does not say. null means that no model has given a probability yet. It does not mean the claim is in doubt. When any claim has a number, models.probabilities must name the model that gave it.

    A value has the type that this page writes for it. A number in quotes, such as p: "0.5", is rejected, and so is true where a number belongs.

    A bounds file writes its claims and its passages the same way.

    Samples and shared claims¶

    Each row under samples holds the claims of one sample, each under its label. shared holds claims in the same form.

    A sample has every claim under shared, except for a label that its own row writes. The row's claim replaces the shared claim whole: no field of the shared claim carries over. In the example, the two input rows replace the shared target and the shared control_type.

    After that rule is applied, every sample must have all 18 labels below. A gap is written as unknown or na, so a label that is absent was forgotten, and the check rejects it.

    Label Holds
    biosample The piece of material the library was made from. Its id is required. Two samples with one id were made from the same material.
    donor The person or animal the material came from. Its id names the individual. na when the material is a pool or has no single individual.
    assay The kind of sequencing experiment, such as RNA-Seq or ChIP-Seq. Term: EFO, such as EFO:0008896 for RNA-Seq.
    target What a pull-down enriches: a histone mark or a protein. na for an assay with no pull-down, and for a control library. No term. Never a factor.
    control_type The kind of background-control library, such as input or IgG. na for every other library.
    species The species. Term: NCBI Taxonomy, written NCBITaxon:9606. Must be quoted or inferred.
    sex The sex. Term: one of female, male, hermaphrodite, mixed.
    age The age, with value and unit.
    development_stage The stage of life, such as fetal, larval or adult. Term: the stage list of the species (HsapDv, MmusDv, WBls, FBdv). A rat stage has no list and no term.
    tissue The tissue or organ. Term: UBERON, or WBbt for C. elegans.
    cell_type The cell type. Term: Cell Ontology (CL).
    cell_line The cell line. Term: Cellosaurus.
    disease The disease or disease model. Term: MONDO, or PATO:0000461 for healthy.
    genotype The genotype, as text.
    strain The strain, as text.
    treatment What was applied to the sample. Term: ChEBI for a chemical, or a list of ChEBI ids when one sample got several compounds. A protein keeps its text with no term.
    dose How much of the treatment, with value and unit for one number. Text alone when no single number applies, such as "per side".
    duration How long the treatment was applied, with value and unit for one number. Text alone when no single number applies, such as "overnight".

    Tissue, cell type and cell line are three labels, and a sample can have a value in each.

    Four points of meaning matter when you write or read these labels. The check does not test them.

    • control_type is about background-control libraries only. An input library or an IgG library measures the background of a pull-down. An untreated or wild-type group that the study compares the others with is a comparison baseline, not a control. Its control_type is na, and the factor's baseline names it.
    • duration is the length of the treatment itself. Any other time is an attribute of the study's own. The time from the end of a treatment to the harvest is one example.
    • An untreated sample in a study that treats writes its text. Its treatment says what it got, such as "untreated" or "vehicle (PBS)", and is not na. na on treatment is for a study with no treatment. The route, the side and what a time is measured from stay in text.
    • A pull-down library and its control are tied by the biosample id. No other field ties them. In the example, each input has the id of the pull-down made from the same chromatin. This tie has a known limit. One control library that serves pull-downs made from different material cannot be tied to all of them, because the control has one biosample id.

    A row or shared may hold more labels than the 18. Such a label is an attribute of the study's own, such as time_of_day in the example or a harvest time. Its claim has the same form.

    The rules for a claim's term and value, by its label:

    • A sex term is one of the four words female, male, hermaphrodite and mixed.
    • Any other term is an id from the vocabulary that the table above names for the label and the sample's species, such as UBERON:0002107 for a mouse tissue and WBbt:0005772 for a worm tissue. A shared claim must fit the species of each sample that it stands for. On disease, PATO:0000461 for healthy is allowed too.
    • A label for which the table names no vocabulary takes no term. These are target, control_type, genotype, strain, age, dose and duration, a rat's development_stage, and a label of the study's own.
    • Only age, dose, duration and a label of the study's own take a value.

    Factors¶

    A factor is a label that the study varied on purpose, such as the treatment in a drug study or the age in an aging study. factors is keyed by that label. A sample's value is written once, in the sample's claim on the label. The factor adds the list of levels and how they compare.

    Field Holds
    levels The names of the levels, each a short text. For an ordered factor, the order of this list is the order of the levels.
    baseline The level the study compares the others with. null when the study compares the levels with each other and none is a reference, such as two tissues. Required.
    ordered true when the levels run along a scale, such as a time course or a dose series. Otherwise false.
    a backing mark, see, p A factor is a claim too. It is backed by quoted, inferred or unknown.

    The rules for a factor:

    • Its label must be a label of every sample. Where the label does not apply to a sample, the sample's claim on it is na.
    • baseline is one of levels, or null.
    • No level is named twice. A level name is text: quote a name that YAML reads as a number, as "0".
    • At least one sample is at each level in levels.
    • A sample's claim on the factor's label names its level in level, with one of the names in levels. Two samples with different text and the same level are at the same level.
    • A claim with no level on a factor's label means that the factor does not cover that sample. An example is a study that varied the genotype among its RNA-Seq samples only.
    • When the claim under shared names a level, a row's claim that replaces it names a level too. A row's claim that is unknown or na is the exception, because it names none.
    • level on a label that is not a factor is rejected.
    • target is never a factor. The relations already keep samples with different targets apart, and a target has no baseline. A factor keyed target is rejected.

    The check¶

    seqforge study check-reading <file> reads one file and prints one JSON object:

    {
  "file": "reading.yaml",
  "format": 2,
  "valid": false,
  "problems": [
    {"field": "samples.GSM9000003.strain", "reason": "missing: every sample has this label, in its own row or under shared"},
    {"field": "shared.assay.quoted", "reason": "passage 7 does not exist"}
  ]
}

    It exits 0 for a valid file, 3 for a rejected one, and 2 for a file it cannot read. A file that is not UTF-8 text cannot be read. Each problem names the field and the reason. samples.GSM9000003.strain is the strain claim of that sample.

    A key that one mapping writes twice is rejected, and the problem names the key. Plain YAML keeps the last of the two and reports nothing, so a second row for one sample would replace the first unseen.

    The check asks only whether the file is well formed. It reads the file alone and opens no record, so it does not look for a quote in its source, and it does not judge whether a claim is right.

    The relations¶

    A reading does not store which samples are replicates or which groups the study contrasts. Those follow from the claims, so seqforge study relations <file> works them out on every run and writes no file. The command checks the file first and rejects a broken file exactly as check-reading does. For a valid file, the JSON object has one more field, relations.

    Three terms define the relations:

    • Two samples have the same assay, the same target or the same control type when the two claims have the same text, or are both na, or are both unknown.
    • A group is the set of samples that have the same assay, target, control type and level on every factor. A group can be one sample.
    • A control library is a sample whose control_type claim is quoted or inferred. A sample whose control type is unknown is not a control library.
    • A signal is a sample whose target claim is quoted or inferred and that is not a control library.
    Relation Holds
    replicates Each group of two or more samples: the same assay, target, control type and level on every factor.
    contrasts Each pair of groups that have the same assay and target and differ in the level of exactly one factor. Neither group is a control library. One of the two is at the factor's baseline. For a factor with a null baseline, each pair of levels is one contrast.
    series For each ordered factor: the samples in level order, among the samples that have the same assay, target, control type and level on every other factor. So input libraries and IgG libraries never share a series. A series has at least two levels.
    shared_biosample Each set of two or more samples with one biosample id.
    signal_to_control Within one such set: each signal, paired with each control library.

    For the example above, the command prints these relations. Samples, factors and levels are listed in the file's order. The picture shows the same relations, and the JSON follows it.

    When the format changes¶

    There is one format at a time. format is a whole number, and the check accepts only the current one. A file with another number is rejected, and the message names the number the check expected.

    A change to the format raises the number and rewrites every existing file in the same change. No file stays behind in an older format, and git history is the only record of the old form.
