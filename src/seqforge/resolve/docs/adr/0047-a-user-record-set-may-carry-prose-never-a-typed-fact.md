# 47. A user-written record set may carry prose, never a typed fact

ADR-0034 refused `attributes` and `free_text` together, and only the first refusal was load-bearing:
an attribute reaches `asserted` by being *typed*, since `_positions_for` copies a record's slot
straight into a position, so it is believed for where it sits and arrives with no origin at all —
that stays refused. Prose reaches nothing by being written; it becomes a document, and a claim leaves
it only carrying a quote that greps back and a value that quote entails. The objection that killed it
was that such a quote greps back against a file its own author wrote to be grepped — true, and not a
distinction, because ADR-0034's own remedy is "write it in a README and harvest that" and a README is
equally a file the author wrote this morning and can edit after. So the circularity cannot be what
separates them; what separates them is that a README is dataset-scoped, which `_basis_for` grades
`inferred` and fans to every sample at once. For a 784-worm plate spanning nine ages and three
strains that is not a weaker answer but a wrong one, and there was no third option: sample-scoped
documents were reachable only through an archive, which pre-deposit data does not have. What prose on
a record buys is therefore not credence but *subject* — which sample the words are about — plus a
mandatory `label` naming where they came from, so `strain=CF` read out of `directory_name:
day13_CF_26` is visibly a filename convention rather than a bench measurement, and a reader can weigh
it. The cost is real and is the trade: a lab that writes its own prose can now reach `asserted`, the
grade an archive's transcript gets, and nothing but that label distinguishes a careful record from a
careless one.
