# 54. The retained archive is partitioned by mappability, and on a Chimera unique is per Component while multi is not

One archive per cell held every primary mapped record together — on a chimeric run under
`chrI<sep>ce11` names a browser, a counter and any script the user already owns all refuse, while the
split's properly spelled per-Component output was reclaimable and deleted. It is two artifacts now.
Uniquely placed is CRAM per Component, cut from that Component's split BAM and encoded against that
Component's own reference, so one assembly's names, order, lengths and binary dictionary are what a
record resolves through; both Components of the built Chimera resolve standalone with a `.fai` beside
them, checked before this shipped, or this half would have been BAM. Multiply placed is ONE
Component-blind file per cell in Chimera coordinates, cut from the pre-split alignment so it and the
split both see what the aligner wrote: one emitted record cannot say whether a fragment's other loci
are in the same organism, so filing that population per Component would state an assignment, and a
Component-blind file beside per-Component ones would add nothing a suffixed name does not already say.
The plain twin partitions identically, and the halves being exactly every primary mapped record is why
the whole-Chimera archive is gone rather than kept: nothing lost, no bytes duplicated. The caveat —
one of this fragment's possible loci is here, never that the fragment belongs here — rides the name
and a `@CO` header line, because a docstring does not travel with a file someone copied.
